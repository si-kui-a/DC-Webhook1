# 提醒推播流水線

建立：2026-10-08

東海行事曆、勵學基金、已報名活動三種提醒，從資料進來到送達、驗證、修復的完整流程。設計理由在 `docs/DECISIONS.md`，排程本身的操作在 [CLOUD_SCHEDULER.md](CLOUD_SCHEDULER.md)。

## 流程

| 階段 | 做什麼 | 由誰／什麼執行 |
|---|---|---|
| 1. 資料進來 | 行事曆、勵學基金公告每天自動抓；已報名活動要加入 | 自動；活動用 `python scripts/add_thu_event.py -`（貼上報名信，原文不存檔，自動同步 Secret） |
| 2. 觸發 | 每小時一次 | Apps Script 觸發器（主要）、GitHub 排程每 3 小時（備援） |
| 3. 預約 | 提醒點在 75 分鐘內就預約整點送出；提醒點對齊 5 分鐘 | `jobs/precise_send.py`（每日提醒 06:00；活動前 7 天、1 天、3/2/1 小時） |
| 4. 送出 | 預約的工作睡到提醒點，送出時重新產生訊息（活動刪除就不送） | `.github/workflows/send_at.yml` |
| 5. 驗證與補送 | 提醒點過 15 分鐘後確認送出成功；失敗或沒跑就補送（訊息標「補送」） | 每次觸發的 `precise_verify` |
| 6. 監控 | 觸發間隔超過 3 小時推警告到 EDU bot；每次觸發 ping Healthchecks；Apps Script 失敗時 Google 寄信 | 自動 |
| 7. 健康檢查 | 一個指令看觸發頻率、送出失敗、Secret 是否同步、token 到期、接下來 7 天的提醒 | `python scripts/reminder_health.py`（每項 TODO 都附修法） |

## 修復

| 症狀 | 原因 | 處理 |
|---|---|---|
| 收到「雲端排程 N 小時沒有執行」 | Apps Script 觸發器停了或 token 過期 | script.google.com →「DC-Webhook1 hourly trigger」→ 執行項目看錯誤；token 過期就換新（人工核對清單的 `gas_token_renewal`） |
| 收到「補送」 | 預約的送出工作失敗 | 已自動補送；連續出現就到 Actions 的 send-at 看失敗原因 |
| 新增的活動沒提醒 | Secret 沒同步 | `python scripts/reminder_health.py` 會指出，執行 `python scripts/add_thu_event.py --sync` |
| 同一則提醒重複 | 手動重跑已完成的任務 | 手動執行預設會跳過今天已成功的任務；只有勾 `force` 才會重送 |
| 提醒時間不對 | 活動資料或預約錯誤 | `reminder_health.py` 列出接下來的提醒時間核對；活動有誤就重新加入報名信 |

## 例行

| 何時 | 做什麼 |
|---|---|
| 報名新活動 | 把報名成功信加入（階段 1） |
| 收到警告或補送 | 照「修復」表處理 |
| 每月一次或覺得怪怪的 | `python scripts/reminder_health.py` |
| token 到期前 | 人工核對清單會列出，照該項換新 |
